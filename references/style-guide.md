# GitHub 风格与编辑约定

## 视觉参数

这些参数固定当前 skill 的输出，不提供 38 种主题切换。

| 元素 | 参数 |
| --- | --- |
| 正文 | 16px，行高 1.75，系统无衬线字体 |
| 短语高亮文字 | `#0550AE`，字重 `600`，左右各 `2px` 内边距、上下 `0` |
| 短语高亮衬底 | `linear-gradient(transparent 58%, rgba(9,105,218,0.14) 58%)` |
| 卡片底色 | `#FFFFFF` |
| 卡片圆角 | `12px` |
| 卡片内边距 | 上下 `20px`、左右 `22px` |
| 卡片阴影 | `0 6px 24px rgba(0,0,0,0.07)` |
| 卡片边框 | 不使用紫色竖线，不使用紫底 |
| H2 | 标题下方保留蓝色线条；标题上方无 `hr`、渐变线或其他装饰分隔线 |
| END 文字 | 蓝色 `#176BB7`，加粗；两侧使用浅蓝色可见 `─` 字符 |
| END 互动文案 | 灰色 `#999999`，居中 |

衬底占文字行内盒下部约 42%，不是固定像素高度，也不是段落 28px 行高的 42%。白底上透明浅蓝约呈 `#DDEAFA`。若用户要求完全沿用样式，不可用公众号的整块文字背景色悄悄替换渐变。

## 内容标记

- `## 小标题`：章节标题，下方有蓝线。
- `**关键词或短判断**`：浅蓝衬底强调，保留原文字符。
- `> 原文中的完整重点段落`：白底圆角阴影卡片。
- 页尾自动生成 END。若原稿已经有 END 模块，先避免重复；正文中的普通英文单词 end 不应被删除。
- 文章题目独立处理，不把文件名、作者括号前缀、平台标签自动识别成正文小标题。
- 不把 `#ai` 等平台标签误判成 `# 一级标题`；Markdown 标题需要 `#` 后的空格。

Markdown 中的 `**` 和 `>` 是排版标记，不应在成品正文中外露。强调若跨多个自然段，应拆为各自独立的短语，不把卡片或多个段落包进同一行内元素。

## 选择重点

先找到文章的中心判断，再标出每个论证部分值得记住的短语。可以强调约束条件、作用机制、对比中的差异和最终建议；专有名词并不天然比论点重要。

例如“客户不会因为多一个按钮就改变原有工作方式，真正的门槛是迁移成本”，适合强调“迁移成本”，也可以视上下文强调“改变原有工作方式”；不应只因为“客户”出现频繁就到处加蓝。

参考密度是约 1000～1500 字普通论说文 8～16 处短语强调。需要自检的是：文章中后部是否完全没有重点、一个段落是否出现多段相邻高亮、是否给重复出现的词每次都加蓝，以及单独阅读重点是否仍能理解文章结构。密度服从内容，不能用配额反推强调内容。

## 复制与验收边界

公众号正文只复制文章内容，不复制工具栏、操作提示、标题输入框或调试信息。复制使用富文本 HTML 和普通文本两个剪贴板类型；纯文本路径仍应保留 END 两侧的横线。

字体、颜色、卡片和横线应内联于正文，不依赖预览页的外部样式表。不要将 `text-align: start` 等非预期值带入正文；使用 `left`、`center`、`right` 等标准值。

渐变与阴影是为视觉一致保留的效果。微信公众号可能警告渐变在深色模式中的表现，也可能剥离某些样式。不能把“浏览器检查通过”写成“微信公众号官方兼容检查通过”。需要零渐变告警的版本时，应先解释视觉差别，再按用户选择制作，而不是在原参数下承诺零告警。

编辑器打开后修改的是内存中的当前稿。磁盘上的初始 `article.html` 不会自动改变；保存时应导出当前稿，交付或分享时核对所用版本。
