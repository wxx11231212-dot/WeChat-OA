# WeChat OA

WeChat OA 是一个只保留 GitHub 风格的微信公众号排版 skill。输入 Markdown、文本或 Word 文档，生成可以离线打开的编辑页面：先预览和调整重点，再复制到公众号后台。

GitHub 仓库：[wxx11231212-dot/WeChat-OA](https://github.com/wxx11231212-dot/WeChat-OA)。

本项目的需求与视觉方向来自 [xiaohuailabs/xiaohu-wechat-format](https://github.com/xiaohuailabs/xiaohu-wechat-format) 的 GitHub 主题。这里独立编写渲染器和编辑器，不包含原项目的 38 主题引擎，也不是原项目的官方版本。感谢原项目提供的思路。

## 固定风格

| 部位 | 效果 |
| --- | --- |
| 重点文字 | 深蓝文字，字面下半部浅蓝衬底，可选词增加或取消 |
| 重点卡片 | 白底、12px 圆角、浅灰阴影，无紫底和左竖线 |
| 小标题 | 保留下方蓝色线条，去掉标题上方细分隔线 |
| 文章结尾 | 带左右可见横线的 END，以及灰色互动文案 |

工具不会要求联网、登录或连接公众号。它生成的是富文本，发布仍在公众号后台完成。具体样式参数见 [样式说明](references/style-guide.md)。

## 安装为 skill

需要 Python 3.10 或更新版本。

仓库名称使用 `WeChat-OA`。下载仓库后，将包含 `SKILL.md` 的仓库根目录复制到 Codex 的 skills 目录，并将文件夹命名为 `wechat-oa`，例如 `~/.codex/skills/wechat-oa`；Windows 下通常是 `%USERPROFILE%\.codex\skills\wechat-oa`。在该文件夹中执行：

```bash
python -m pip install -r requirements.txt
```

然后在新的对话中使用：

```text
用 $wechat-oa 排版这篇文章。保留原文，根据内容标出重点，生成可以修改高亮并直接复制到公众号的版本。
```

如果使用 Codex 内置的 skill-installer，选择本仓库根目录 `.`，安装名称为 `wechat-oa`。无需先安装原版 skill。

## 直接运行

不使用 skill 时也可以在仓库根目录运行：

```bash
python scripts/render.py --input examples/demo.md --output output/demo --open
```

把 `--input` 换成自己的 `.md`、`.txt` 或 `.docx` 文件；路径有空格时用引号包住。

| 参数 | 用途 |
| --- | --- |
| `--input` | 原文章文件 |
| `--output` | 生成文件夹 |
| `--title` | 可选，指定文章标题 |
| `--highlights suggest` | 默认模式，在没有人工标注的内容中使用规则建议重点 |
| `--highlights preserve` | 只保留输入中的强调，不额外推荐；适合经人工或 skill 语义选择后的 Markdown |
| `--no-end` | 可选，取消自动 END 页尾 |
| `--open` | 可选，生成后在默认浏览器中打开 |

`suggest` 是确定性规则辅助，并不是脚本内置了语义模型。使用 skill 时，会先阅读原文、按论点选择重点，再渲染 `preserve` 版本。普通论说文以重点清楚且分布合理为目标，不机械凑数量。

## 排版与复制

1. 用浏览器打开生成的 `preview.html`。
2. 在正文中选中一小段文字，使用页面的高亮操作增加或取消浅蓝衬底。选择核心判断和关键短语，避免整段刷蓝。
3. 标题单独复制到公众号标题栏，再复制正文到正文编辑区。不要使用“粘贴为纯文本”。
4. 编辑后需要留稿时，使用页面的导出功能保存当前稿。`article.html` 是最初渲染时的快照，不会随浏览器操作自动更新。
5. 在公众号手机预览中检查高亮、卡片、换行与 END。

预览页可以整体发给别人离线使用。文件在浏览器中以 `file://` 地址打开时，地址栏显示接收者本机的文件位置；需要团队共用的 HTTPS 地址，应把生成页面另行放到静态网页托管服务。skill 本身不替用户发布网站。

## 输出

| 文件 | 内容 |
| --- | --- |
| `preview.html` | 自包含预览与高亮编辑器，可复制当前正文 |
| `article.html` | 初始版本的公众号正文富文本片段 |
| `article.md` | 处理中间稿，便于检查和继续排版 |
| `metadata.json` | 标题与生成信息 |
| `assets/` | Word 文档中的图片等资源，存在时生成 |

Word 导入以文章内容为主，不保证还原所有 Word 复杂版式；检查表格、脚注和图片。本地常见位图会嵌入预览文件，公众号可能需要在后台重新上传图片。外链图片的显示仍需要网络。

## 开发验证

在仓库根目录执行：

```bash
python -m unittest discover -s tests -v
```

测试覆盖原文与代码保留、卡片与 END、标题分隔线、DOCX 内容及图片提取，以及不受信任 HTML 的处理。交互编辑器还需在浏览器中检查局部取消高亮、跨段选区、撤销重做、正文复制和导出后重新打开。

## 兼容性

浅蓝衬底沿用所需的渐变效果，卡片使用 CSS 阴影。浏览器预览正确、富文本复制成功，并不等于公众号所有终端都会保留每项样式。公众号可能提示渐变相关风险，也可能过滤阴影或调整深色模式颜色。请以实际粘贴后的手机预览为准。

END 两侧使用可见的 `─` 字符，避免只靠边框线条导致复制后消失。正文中不插入小标题上方的装饰性分隔线。
